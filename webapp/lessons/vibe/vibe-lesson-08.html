Phase 2: The Shell

UI 組件與設計（shadcn/ui）

透過 AI 直接貼出完美 Tailwind CSS 代碼，快速打造一致的註冊頁面體驗

🎯 課程核心概念與 AI 角色

在 Vibe Coding 的流程中，UI 設計不再是需要設計師單獨完成的中斷步驟，而是與邏輯開發同步進行的持續迭代。對於 Independent Developer 來說，shadcn/ui 扮演了關鍵的橋樑角色：它提供了一種「複製並貼上即可使用」的現代化組件庫模式，而不是傳統需要大量配置和修改的 NPM 套件。這使得 AI Agent 能夠極其高效地介入——你只需描述想要的界面，AI Agent 就能直接吐出包含完整 Tailwind CSS 類別的 React 組件代碼，且完全符合你現有的專案設定（如色版、字型）。當 Vibe 破裂，例如出現樣式覆蓋或組件功能異常時，因為所有代碼都在本地可見，你可以直接檢查 Tailwind 的 `tailwind.config.ts` 設定或組件的 props 傳遞是否正確，這種可視化的優勢讓 Debugging 變得直觀且迅速。

⚖️ shadcn/ui 與傳統 NPM 套件對比

為什麼在 Vibe Coding 的 AI 工作流中，開發者更傾向選擇 shadcn/ui 而非 Material UI 或 Ant Design？這在於開發體驗的本質不同。傳統套件像是黑盒，你依賴它們的版本發布和內部實現，一旦遇到樣式衝突或想要微調一行 CSS，往往需要尋找特定的 class name 或使用 `!important` 強制覆蓋，這非常容易導致 Vibe 破裂且難以修復。相反地，shadcn/ui 的原始碼就在你的項目文件夾裡（位於 `components/` 和 `lib/` 目錄下），每一個組件都是獨立的、可導出的 React 組件，完全由你自己掌控。AI Agent 喜歡這種模式，因為它能直接操作你的代碼文件，根據你的需求修改組件內部邏輯或 Tailwind 類別，而不必擔心版本不相容。當你需要一個自訂的輸入框，AI 可以直接在現有的 input 組件基礎上修改，而不是引入一個新的包。這種「擁有權」感讓迭代速度飛快，也讓故障排除變得更透明。

🔧 初始化 shadcn/ui 環境範例

在使用 shadcn/ui 之前，必須先將該技術棧整合到 Next.js 專案中。這個過程並非隱形，而是顯性的指令序列，你需要通過終端機初始化配置，讓 AI Agent 知道如何生成組件。正確的初始化步驟包括安裝 CLI 工具並配置你的基本檔案路徑。以下是常見的初始化流程與輸出示範，請注意觀察其中的錯誤處理與確認提示，這些都是在 Vibe Coding 過程中會經常遇到的交互點。

$ npx shadcn-ui@latest init # 詢問：What is your project's type? (app | pages) app # 詢問：What is the URL of your project? (http://localhost:3000) http://localhost:3000 # 詢問：Where would you like the components to be created? (components) components # 詢問：What would you like to call the component namespace? 💡 AI 如何生成與診斷註冊頁

當你希望 AI Agent 幫助你搭建一個註冊頁面時，直接說出需求即可，例如：「幫我寫一個使用 shadcn/ui 的註冊表單，包含電子郵件、密碼、確認密碼欄位，並加上驗證錯誤訊息提示。」AI Agent 會回應完整的 `RegisterForm.tsx` 組件代碼，其中使用了 `Input`, `Button`, `Form`, `Label`, `FormField`, `FormMessage` 等標準組件。如果 Vibe 破裂，例如發現錯誤訊息沒有顯示出來，通常是因為沒有正確連接 `react-hook-form` 或者 `FormMessage` 被放置在了錯誤的位置（必須包在 `FormField` 內）。另一個常見問題是 Tailwind 樣式失效，這可能是因為你在組件中手動修改了 class name 但未在 `tailwind.config.ts` 的 `content` 路徑中加入新文件路徑，導致構圖時未被掃描到。這時應檢查 `next.config.mjs` 或 `tailwind.config.ts` 中的內容配置，確保包含了 `pages/**/*.{ts,tsx}` 或 `app/**/*.{ts,tsx}` 等路徑。

🔬 深度解析：為什麼 AI 偏好 shadcn/ui？
為什麼 AI Agent 在編寫 UI 代碼時更鍾意 shadcn/ui 這種可編輯模式？

AI Agent 之所以特別青睞 shadcn/ui，背後有兩個核心的技術與架構原因。第一，它是「代碼優先」而非「API 優先」的設計哲學。傳統的 UI 套件透過 JavaScript 函式呼叫來渲染元件，對於 AI 來說，這意味著它必須準確理解套件的內部物件結構與 prop 定義，稍有偏差就可能產出無法運轉或樣式錯亂的程式碼。但 shadcn/ui 本質上是 Pure Component + Tailwind Class，AI 只需要套用文字模式去組合 Class Name 與 JSX 結構即可，這種生成方式更接近自然語言描繪的直覺，錯誤率大幅降低。第二，也是更重要的，是可維護性與可調適性。在 Vibe Coding 中，需求是快速變動的。當客戶說「把按鈕變成紅色且圓角更大」時，AI 不需要去查閱某個外部庫的文檔或考慮版本更新風險，它直接打開本地的 button.tsx 檔案，修改其中的 className 字串即可。這種「即改即得」的能力，使得 AI 能像人類開發者一樣進行細粒度操作，從而大大提升開發節奏與準確度。此外，由於所有組件都在 git 管理下，AI 生成的代碼也能被版本控制追蹤，協作無縫銜接。

請先回答，再點擊「查看答案」

1. 在 shadcn/ui 中，以下哪種情況最有可能導致 Form 驗證錯誤訊息 (FormMessage) 無法顯示？
  • 沒有安裝 zod 套件來定義驗證規則。
  • FormMessage 組件沒有被包裹在 FormField 組件內部。
  • 沒有在 tailwind.config.ts 中註冊 components 路徑。
✅ 正確答案是 B。shadcn/ui 的 Form 組件依賴於 react-hook-form 的上下文作用域，FormMessage 必須嵌套在其對應的 FormField 裡才能綁定特定的 field name 並獲取 error 狀態。若未包裹，即使 form 有錯誤也不會觸發顯示。A 選項错误，因為驗證規則雖重要但非顯示的必要條件；C 选项错误，因為 components 路徑影響的是組件掃描而非運行時行為。
2. 當使用 AI Agent 生成 shadcn/ui 組件後，發現自定義的 Tailwind Color 未生效，最可能的原因是什麼？
  • npm install 時安裝了錯誤版本的 tailwindcss。
  • tailwind.config.ts 的 content 陣列未包含新增的組件文件路徑。
  • AI Agent 沒有使用正確的組件導入語法。
✅ 正確答案是 B。Tailwind 在構建時只會掃描 content 配置中指定的文件路徑內的 class name。如果你建立了新的組件文件卻沒將其路徑加入 content 陣列，那麼即使你在組件中使用了指定的自訂 color class，編譯器也會忽略它們，導致樣式失效。A 选项通常不會只影響單一套裝顏色；C 选项會導致報錯而非無效樣式。
🚀 今日任務

請依序完成以下練習

  1. 任務一：在你的 Next.js App Router 專案中，執行 `npx shadcn-ui init` 完成初始化配置，並確認 `.shadcn/config.json` 已正確產生。
  2. 任務二：使用 `npx shadcn-ui add button input form` 指令註冊三個基礎組件，然後觀察本地 `components/ui/` 目錄下是否成功生成對應的 TypeScript 檔案。
  3. 任務三：請你對 AI Agent（如 Cursor 或 Claude Code）下達指令：「請幫我建立一個註冊頁面，包含 Email、Password、Confirm Password 三個欄位，並使用 shadcn/ui 的 Form 元件進行串接，確保錯誤訊息正確顯示。」將生成的代碼複製到你的 `page.tsx` 中並測試提交功能。
  4. 任務四（Vibe Debugging）：故意將任務三中生成的某一個 `FormField` 的 `name` 屬性改為無效字元（例如 `""` 或不存在的 field name），觀察表單是否還能正常驗證。然後修復代碼，並記錄你如何通过檢查組件樹結構來發現問題。
