Phase 3: The Brain

向量資料庫與 Embedding 實戰

用 pgvector 把文字轉成向量，實現語意搜索與 RAG 檢索

1 核心概念：向量是什麼？為什麼需要它？

文字本身對計算機來說是無法直接比較相似度的字串，但透過 Embedding 模型可以把一段文字轉換成一個數位向量（例如 768 維的數值陣列）。這個向量的每一個維度都承載著語意資訊，語意相近的內容在向量空間中的幾何距離也會相近。pgvector 是 PostgreSQL 的開源擴展，讓 Supabase 這類關聯式資料庫能直接儲存與計算向量，不用另外架設 Milvus 或 Pinecone。對 Vibe Coding 而言，這代表你的資料庫同時具備「精確篩選」與「語意模糊匹配」兩種能力，AI Agent 在實作 RAG 系統時可以完全依賴單一資料庫後端，減少組件間的整合成本與網路延遲。

2 傳統資料庫 vs. 向量資料庫

當你需要搜尋「如何修復 macOS 終端機報錯」時，關鍵字搜尋只會比對字面，而語意搜尋能理解「bash 錯誤排除」與「terminal command failure」是同一段需求。

傳統關係型搜尋
SELECT * FROM docs WHERE content LIKE '%bash%'; -- 只能比對字串，語意相近但用詞不同的記錄不會被找到
向量語意搜尋
SELECT * FROM docs ORDER BY embedding <=> '[0.12, -0.45, ...]' LIMIT 5; -- 根據向量距離排序，找到語意最相近的紀錄，無論用詞是否相同
3 實戰：在 Supabase 開啟 pgvector 並搜尋

首先要在 Supabase 專案中啟用 pgvector 擴充套件，接著建立带有 vector 型別的資料表，最後用 cosine distance（<=> 運算子）進行語意相似度排序。以下是完整的流程範例，包含安裝指令、建表語法與查詢語法。

$ supabase db push # 啟用 pgvector 擴充套件（若尚未啟用） $ supabase functions deploy get-embedding --env-file .env.local Error: function "get-embedding" not found # 若函數尚未建立，需先完成 Edge Function 設定 $ psql postgresql://... -c "CREATE EXTENSION IF NOT EXISTS vector;" CREATE EXTENSION
🔬 深入解析：Embedding 是如何產生語意距離的？
為什麼「蘋果手機」和「iPhone」的向量會比較接近？

Embedding 模型的訓練過程是透過大量文本資料，讓模型學習每個詞彙或句子在語境中的分佈特徵。當一段文字被輸入模型後，會經過多層神經網路轉換，最終輸出固定長度的浮點數向量。這個過程的本質是「語意壓縮」：意義相近的文字在向量空間中會傾向聚集在同一區域。例如模型在訓練時看過「Apple iPhone 手機 智慧型裝置」等共現關係，就會把「蘋果手機」與「iPhone」映射到相近的座標。pgvector 提供 L2 distance（<->）、inner product（<#>）與 cosine distance（<=>）三種距離計算方式，語意搜尋通常使用 cosine distance，因為它只看方向不看長度，更能反映語意相似度而非絕對數值差異。

🛠️ Vibe 破裂診斷：常見錯誤與修復

當語意搜索查詢失敗時，最常見的原因有三種：一是 pgvector 擴充套件未啟用，系統會回傳錯誤表明找不到 vector 型別；二是向量維度與查詢向量不一致，例如資料表設為 768 維但傳入的 embedding 是 1536 維；三是未建立向量索引，導致查詢效能極差甚至超時。修復步驟包括：先用 supabase db remote commit 確認擴充套件狀態，再用 \d 資料表名稱 檢查向量欄位維度，最後加上 CREATE INDEX ON docs USING ivfflat (embedding vector_cosine_ops); 建立索引。這些問題在 Vibe Coding 中容易因 AI 生成的 SQL 語法不一致而發生，建議用 Cursor 或 Claude Code 的 database schema 檢視功能先確認結構再執行寫入。

1. 在 Supabase 中使用 pgvector 進行語意搜索時，哪個運算子代表 cosine distance？
  • <->
  • <=>
  • <#>
✅ <=> 是 pgvector 的 cosine distance 運算子，用於計算兩個向量之間的餘弦相似度。<-> 是 L2 歐氏距離，<#> 是內積（inner product）。語意搜索通常使用 cosine distance 因為它只比較向量方向而非絕對長度。
2. 當 embedding 維度與資料表欄位設定不一致時，會發生什麼情況？
  • 查詢結果隨機排序
  • Supabase 自動降維後正常執行
  • 資料庫回傳錯誤拒絕寫入或查詢
✅ pgvector 會嚴格檢查向量維度，若寫入的 embedding 維度與欄位定義不符，會直接回傳錯誤如 "vector dimension mismatch"。自動降維或隨機排序都不是實際行為，必須確保 Embedding 模型輸出維度與資料表欄位設定一致。
