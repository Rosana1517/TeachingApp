Vibe Coding 情境下的 Client/Server 元件標記邏輯與實務調用

🎯 核心概念在 Vibe Coding 中的角色與 AI 協作邏輯

在 Vibe Coding 的工作流中，Next.js 的 App Router 不僅是路由系統，更是 AI Agent 理解「服務器態」與「前端動態行為」之間的關鍵介面。當我們使用 `use client` 標記元件時，實際上是在向 AI Agent 發出一個明確的指令：此元件需在瀏覽器環境中執行，具備事件處理、狀態管理或 DOM 操作能力。反之，未被標記的預設 Server Component 則代表此元件應在服務器端渲染，直接輸出 HTML，避免不必要的 JavaScript 傳輸。AI Agent 在生成程式碼時會依據上下文自動判斷是否需要 `use client`，例如當它讀到 `onClick` 或 `useState` 時，會自動插入該指令。若未正確標記，Vibe 將因「伺服器端嘗試操作物件 DOM」而報錯，這是典型的 Vibe 破裂情境。診斷方法包括檢查元件內是否包含瀏覽器 API（如 `window` 或 `document`），或使用 ESLint 插件提示潛在的問題。

⚖️ Server Component 與 Client Component 的標記邏輯對比

當 AI Agent 在撰寫 Next.js 專案時，它必須明確區分哪些元件應該在服務器端執行，哪些需要轉移到瀏覽器。這決定了渲染效率、初始 HTML 大小與互動能力。以下是兩種情境的比較：

情境 A：錯誤標記 - 使用 Server Component 執行 DOM 操作
function DynamicButton() { const handleClick = () => { console.log('Clicked!'); // ✅ 可接受 document.getElementById('btn').style.color = 'red'; // ❌ 錯誤：伺服器無 DOM }; return ; // 缺少 use client } 此程式碼若未加上 `use client`，會在服務器端運行但試圖操作 browser-only API（如 document），導致 Vibe 破裂，因為伺服器環境沒有 DOM 物件，會拋出 ReferenceError。
情境 B：正確標記 - 使用 Client Component 處理互動
'use client'; import { useState } from 'react'; function InteractiveButton() { const [count, setCount] = useState(0); return ( ); } 此元件明確標示為 `use client`，表示它將在瀏覽器中執行，可使用狀態與事件處理，符合 Vibe 運行預期。
🔬 深入解析：為什麼 `use client` 是 Vibe 穩定的關鍵？
為什麼有些元件不能在伺服器端跑？其實不只是效能問題，更是執行環境的本質差異。

在 Next.js 的 App Router 架構中，預設所有元件都是 Server Component，這意味著它們在服務器端被執行、渲染為純 HTML，再傳送至瀏覽器。然而，一旦元件需要使用瀏覽器專有的功能——如 `addEventListener`、`useEffect`、`useState` 或存取 `window` ——就必須將其轉換為 Client Component，也就是透過 `'use client'` 語句宣告。這不是語法糖，而是明確的執行環境切換命令：它告訴 Next.js 與 AI Agent，此元件需打包進 JavaScript bundle，並在客戶端載入後才執行。若未加此標記卻使用了這些功能，Vibe 將會破裂，因為在 Node.js 環境中根本沒有 `window` 或 `document`，導致無法執行或抛錯。這也是為什麼 AI Agent 在生成互動式元件時，必須主動插入 `'use client'`，否則 Vibe 將不穩定。正確的標記不僅是防止錯誤，更是優化傳輸：避免將大量 JS 碼無謂地傳送到無須互動的頁面部分。

✏️ 小測驗

請先回答，再點擊「查看答案」

1. 下列哪一個程式碼片段最有可能導致 Vibe 破裂（報錯）？
  • 一個沒有 `use client` 但僅有靜態文字輸出的 Server Component
  • 一個有 `use client` 標記且使用 `useState` 與 `onClick` 的互動式元件
  • 一個沒有 `use client` 卻在 `componentDidMount`（或等效 `useEffect`）中呼叫 `document.getElementById()` 的元件
✅ 選項 C 是最可能造成 Vibe 破裂的原因，因為它未宣告為 Client Component 卻執行了瀏覽器特有的 DOM 操作，這在伺服器端是不允許的。選項 A 完全合法，是典型的 Server Component；選項 B 正確使用了 `use client` 與 React Hook，符合 Client Component 規範。若出現錯誤，通常是未正確標記或未在 Client 上下文中使用 server-only 函式。
2. 在 Next.js App Router 中，API Routes 存放的正確路徑為何？
  • /app/api/users.js
  • /pages/api/users.js
  • /app/api/users/route.ts
✅ 正確路徑為 `/app/api/users/route.ts`，這是 App Router 標準的 API Route 定義方式，使用 `GET`, `POST` 等方法導出函數。選項 A 是 CommonJS 形式且未符合模組化結構；選項 B 屬於舊版 Pages Router，不適用於 App Router。AI Agent 在建立 API 時，會自動遵循此路徑結構，若手動放置錯誤位置，Vibe 將無法識別 API 端點，導致請求失敗。
