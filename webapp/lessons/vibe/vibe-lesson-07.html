掌握 AI 開發者在 Vibe Coding 時如何精準調用 Client/Server 渲染邏輯

1 Start Here - 認識 Next.js 的渲染分界

在 Vibe Coding 的工作流中，Next.js 不只是框架，更是 AI Agent 需要理解的「執行環境語境」。App Router 與 `use client` 標記機制直接決定了哪些元件由瀏覽器（Client）渲染、哪些由 Node.js 服務器（Server）處理。AI Agent 在生成程式碼時，必須嚴格遵守邊界：服務器元件可以直接存取資料庫或環境變數，而用戶端元件才能操作 `window` 物件或使用 Event Listener。當出現「Vibe Broken」錯誤，例如 AI 在 Server Component 中意外引入了 React Hook 或直接引用 DOM 物件，通常就是因為沒加 `use client` 標記導致運行時環境錯置。理解這個機制，能有效減少 AI 生成的代碼在本地執行時的無法定位錯誤。

2 Client vs Server 環境差異分析

這一段我們將對比不同執行環境下的限制，幫助你在 Vibe Coding 中快速識別 AI Agent 是否需要調整元件屬性。

Server Component (預設)
// AI 默認生成的元件類型 // 可直接讀取環境變數和 DB 連接串 const apiKey = process.env.API_KEY; // 不能使用 useState 或 useEffect function DataFetcher() { // ... }
Client Component (須標記)
// 必須在第一行添加 'use client' 'use client'; // 只能操作瀏覽器 API，無法直接存取服务端變數 import { useState } from 'react'; function InteractiveInput() { const [input, setInput] = useState(''); // 這裡可以使用 DOM 相關的 Hooks }

🔬 Deep Dive - 為什麼 Vibe Coding 要嚴格區分 Client 與 Server？
拆解 Next.js 在服務端與客戶端執行代碼時的權限底層邏輯

Next.js 的核心優化在於「分層渲染」。在傳統單頁應用中，所有 React 元件都在瀏覽器中執行，導致大量 JS 包體積膨脹且加載耗時。Next.js 透過 App Router 允許默認將元件部署到服務器（Server Component），這些元件在構建階段就被編譯為 HTML，不會發送 JavaScript 給瀏覽器，因此能更快呈現內容。然而，這也是 Vibe Coding 中最容易出錯的地方：AI Agent 若未經檢查便在 Server 元件中使用了 `useState` 或 `fetch`（除非有 `cached: false` 等特定選項），Node.js 環境會拋出運行時錯誤，因為這些 API 只在瀏覽器中可用。正確的做法是，只有需要互動（如按鈕點擊、表單輸入）的部分才加上 `'use client'` 標記，將其轉移到客戶端編譯；其餘靜態內容則保留於服務器，利用 Next.js 的服務器端特性自動減少 JS 傳輸量。這種分離不僅提升了性能，也讓 AI Agent 在生成代碼時必須遵循明確的安全邊界，防止敏感環境變數被意外暴露給用戶端。

✏️ 今日知識小測驗

請先回答，再點擊「查看答案」

1. 在 Next.js App Router 中，如果你希望一個元件能夠使用 useState Hook 並且讀取瀏覽器的 localStorage 變數，你必須在這個元件檔案的最頂部添加哪一行代碼？
  • 'use server';
  • 'use client';
  • 'next/client';
✅ 正確答案是 B。在 Next.js 的 App Router 體系中，默認的元件都是 Server Component，它們無法訪問瀏覽器特定的對象（如 window）或使用狀態管理 Hook（如 useState）。為了將元件切換為在瀏覽器中執行，必須在檔案頂部顯式標記 `'use client'`。選項 A `'use server'` 是用於將 Client Component 中的函數定義為服務器動作（Action），用於處理表单提交等場景，而非激活客户端功能；選項 C 是舊版 Next.js 或錯誤的導入路徑，在新版中不存在。
🚀 今日實戰任務

請依序完成以下練習

  1. 任務一：初始化專案。在終端機執行命令建立一個具備 TypeScript 與 Tailwind CSS 支援的 Next.js App 目錄，並確認它能成功跑在 localhost:3000 上。
  2. 任務二：AI 協作測試。開啟你的 AI 編程助手（如 Cursor 或 Claude Code），要求它在專案的 `app/page.tsx` 中建立一個簡單的 React Hook 元件（例如使用 useState 計數器），觀察 AI 是否自動在檔案頂部加入了 `'use client'` 標記。如果沒有，請提示補上並觀察錯誤消失的過程。
  3. 任務三：診斷報錯。刻意在一個 Server Component 中插入 `useEffect` 回調函數且不加入 `'use client'` 標記，觀察控制台會出現什麼樣的運行時報錯（通常是 TypeError 或 Module not found 相關），記錄該錯誤訊息作為未來排錯的參考。
  4. 任務四：API Route 驗證。在 `app/api/hello/route.ts` 文件中撰寫一個 GET 請求處理函數，返回 JSON 資料 {'message': 'Hello from Server'}, 然後透過瀏覽器或 curl 命令驗證該端點是否能正確回應，確認 AI 生成的路由邏輯符合 Vibe Coding 的數據獲取規範。
