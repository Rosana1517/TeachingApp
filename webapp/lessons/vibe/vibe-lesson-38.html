Phase 2: Advanced Agent Engineering

Agent 的動態工具擴展：根據情境即時生成與載入工具

讓 AI Agent 從固定工具集演變為自主擴展的彈性工作流

1 動態工具擴展在 Vibe Coding 中的角色

在 Vibe Coding 的哲學中，開發者期望 AI 能像人類工程師一樣，遇到新需求時能自行延伸能力，而非被預先設定好的工具清單綁手綁腳。動態工具擴展（Dynamic Tool Expansion）指的是 AI Agent 在執行任務時，能根據當前上下文動態生成、載入或呼叫未預先定義的工具。這在 Vibe Coding 中扮演著「無限潛在能力」的角色：Agent 不再受限於開發者事先編寫的工具，而是能即時根據問題需求創造新工具，例如在開發過程中需要一個特定的 API 轉換格式，Agent 能自動撰寫並註冊一個新的工具函數。AI Agent 調用這個技術的方式通常透過「自我反思」機制：當現有工具無法滿足需求時，Agent 會評估是否需要新工具，然後利用程式碼生成能力（例如透過 LLM）即時產生工具定義（包含名稱、描述、參數、實現邏輯），並註冊到當前的工具註冊表中。這種動態性讓 Vibe Coding 從「預設流程」邁向「適應性流程」，但也帶來了可觀測性與安全性的挑戰。

2 對照：預設工具集 vs. 動態擴展

在傳統 Agent 架構中，工具是靜態預設的；而動態擴展讓 Agent 能根據情境即時演化其能力。

預設工具集（靜態）
const tools = [ { name: 'read_file', description: '讀取檔案內容', ... }, { name: 'write_file', description: '寫入檔案', ... } ]; // 工具清單在啟動時固定，無法新增
動態工具擴展（彈性）
// Agent 在執行中檢測到需求，即時生成新工具 const dynamicTool = { name: 'transform_api_response', description: '將 API 回應轉換為指定格式', parameters: { schema: {...} }, implementation: async (params) => { /* LLM 生成實作 */ } }; tools.push(dynamicTool); // 動態註冊到註冊表 // 工具集隨任務演進
3 實作範例：使用 Claude Code 動態新增工具

以下展示如何在 Claude Code 環境中，讓 Agent 根據你的提示動態生成並註冊一個新工具。這種方法讓 Agent 在遇到複雜轉換需求時，能自動擴展自己的能力，而不必依賴開發者事先編寫。

$ claude --dangerously-skip-permissions # 進入 Claude Code 互動模式後，輸入以下提示 "我需要一個工具，能將 JSON 陣列轉換為 CSV 格式，包含隊頭。請生成並註冊這個工具。" # Agent 會回應並執行以下動作： 生成工具定義與實作，並透過 <tool_code> 標籤輸出 JavaScript/TypeScript 程式碼。 執行程式碼，將工具註冊到全局工具注册表。 確認註冊成功後，你可以直接呼叫這個新工具： "請使用 transform_json_to_csv 工具處理 data.json。" # 成功後，你會看到轉換結果；若失敗，錯誤訊息會指出工具註冊或執行問題。 # 注意事項：動態生成的工具需要適當的權限與沙盒環境，以避免不安全程式碼執行。
🔬 深入解析：動態工具擴展的機制與挑戰
為什麼動態工具擴展能讓 Vibe Coding 更強大，卻又更容易出錯？

動態工具擴展的基礎是「元編程（Metaprogramming）」概念：讓程式碼能生成或操作其他程式碼。在 AI Agent 中，這透過 LLM 生成工具定義（名稱、描述、參數結構、實現函數）並即時註冊到執行環境。實現的關鍵在於「工具註冊表」的設計：通常是一個全局物件（如 `window.tools` 或模組匯出的 `toolRegistry`），Agent 需要具備寫入權限，且註冊的工具必須符合可呼叫的介面（例如接受參數並回傳結果）。然而，這種彈性帶來了挑戰：一是安全性，動態生成的程式碼可能包含惡意或錯誤邏輯；二是可追蹤性，當工具是在執行過程中產生的，除錯時難以追溯原始碼；三是成本，生成新工具需要額外的 LLM 呼叫，增加 token 消耗。因此，實作時通常會結合沙盒執行環境（如 Docker 容器）與工具驗證機制（如檢查工具描述是否清晰、參數 schema 是否合理）。在 Vibe Coding 中，開發者需學會監控動態工具的生成與執行，並設定適當的權限限制，以平衡彈性與穩定性。

1. 動態工具擴展的主要好處是什麼？
  • 減少 token 消耗，因為工具生成更精簡
  • 讓 Agent 能根據當前需求即時生成並註冊新工具，提升適應性
  • 完全取代預設工具集，因為動態工具總是更好
✅ B 是正確的，因為動態工具擴展的核心價值在於讓 Agent 能適應未知需求，即時創造所需工具，而不只是依賴預先定義的靜態清單。A 錯誤：動態生成工具反而需要額外 LLM 呼叫，可能增加 token 消耗。C 錯誤：動態工具並不會完全取代預設工具集，因為預設工具提供穩定基礎，且動態生成有安全與成本考量。
2. 當 Vibe 破裂時，如何診斷動態工具擴展的問題？
  • 直接重新啟動整個 Agent，忽略錯誤訊息
  • 檢查工具註冊表狀態、檢視動態生成工具的程式碼與輸出錯誤、確認權限與沙盒環境
  • 假設是 LLM 的隨機錯誤，等待下一次呼叫自動修復
✅ B 是正確的診斷方法：動態工具擴展的問題可能源於工具註冊失敗、生成程式碼有語法錯誤、參數不匹配、或權限不足。需要檢視 Agent 的日誌、工具註冊表內容、以及生成的工具程式碼。A 和 C 都是消極做法，無法解決根本問題，且可能導致問題持續。
