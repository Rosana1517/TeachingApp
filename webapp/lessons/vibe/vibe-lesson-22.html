Phase 4: The Soul

BaaS 核心（Supabase）

讓 AI 為你寫 SQL，打造可擴展的雲端資料層

🗄️ Supabase 在 Vibe Coding 中的角色

Supabase 在本課程中的定位是「AI 可操作的後端基礎設施」。當 Vibe Coding 的 Agent 需要持久化資料時，它會透過自然語言理解需求，直接生成對應的 SQL 指令。這種設計讓開發者不需要手寫複雜的 ORM 查詢，而是讓 AI 扮演資料庫架構師的角色。Supabase 的即時資料庫功能與 Row Level Security 機制，正好符合 Agent 需要動態調整存取權限的需求。值得注意的是，當 Vibe 出現資料不一致的現象時，通常不是 Supabase 本身的問題，而是 AI 生成的 SQL 缺乏適當的約束條件。

⚖️ AI 撰寫 SQL 的兩種路徑比較

當 Agent 需要操作資料庫時，主要有兩種實現方式。第一種是直接生成標準 SQL 語句，這種方式最直接但需要手動處理連線設定。第二種是透過 Supabase 提供的 JavaScript/TypeScript 客戶端庫，讓 AI 生成更符合現代前端開發習慣的程式碼。前者適合需要精細控制資料庫行為的情境，後者則能充分利用框架提供的型別檢查與錯誤處理機制。選擇哪種方式取決於專案的複雜度與團隊熟悉的技術棧。

純 SQL 生成方式
// AI 直接生成的查詢 const result = await supabase .from('users') .select('*') .eq('status', 'active') .order('created_at', { ascending: false }) // 優點：直觀、容易除錯 // 缺點：需手動處理錯誤邊界
TypeScript 客戶端方式
// 帶有型別檢查的查詢 type User = { id: string email: string created_at: string } const { data, error } = await supabase .from<User>('users') .select() .returns<User[]>() // 優點：編譯期錯誤檢查 // 缺點：需要額外定義型別
🛠️ 建立 User Profile 表的 AI 調用流程

當 Agent 接到「建立使用者檔案系統」的需求時，會經歷三個關鍵步驟。首先是解析自然語言需求，轉換成資料庫設計語言。接著根據設計生成 migration 檔案，確保架構變更可追溯。最後是執行 migration 並驗證資料結構。這個過程中，AI 會自動處理外鍵關係、索引設定與預設值等細節。若發生表結構錯誤，通常可以透過查看 Supabase Dashboard 的 SQL Editor 來診斷，或檢查 Agent 生成的 migration 檔案是否有語法錯誤。

🚀 實戰指令：從零開始設定 Supabase

初始化 Supabase 專案有標準化的指令流程。首先安裝官方 CLI 工具，然後建立新專案並啟動本地開發環境。接著透過 Web UI 建立資料表，或使用 migration 檔案進行版本控制。每個步驟都有對應的 CLI 指令，讓 AI Agent 可以自動化整個設定過程。

🔬 AI 生成 SQL 的技術原理
為什麼 AI 能準確將自然語言轉成正確的 SQL？

AI 生成 SQL 的能力建立在兩個技術基礎之上。首先是大型語言模型對 SQL 語法的深度訓練，這些模型在龐大的程式碼庫中學習了各種資料庫查詢模式。其次是 Supabase 提供的 schema 資訊，這些結構化資料讓 AI 能了解表格的欄位類型、約束條件與關係定義。當自然語言轉換成 SQL 時，模型會先解析語意意圖，然後根據提供的資料庫結構生成符合語法的查詢。這個過程之所以可靠，是因為 SQL 本身具有嚴格的語法規則，而資料庫的 schema 定義提供了足夠的上下文資訊。當 Vibe 破裂時，最常見的原因是 AI 對資料庫結構的理解不完整，或是生成的 SQL 與實際 schema 不匹配。
