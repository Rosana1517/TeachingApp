Phase 6: The Shield

容器化（Docker）

一次構建，到處運行，杜絕「在我電腦上沒問題」的困境

1 什麼是 Docker？它在 Vibe Coding 裡的地位

Docker 是一種容器化技術，核心價值在於環境隔離與部署一致性。在 Vibe Coding 中，當你依賴 AI 生成代码時，環境變數、依賴版本、作業系統差異最容易導致「Vibe 破裂」。Docker 讓你能把整個運行環境（Node.js 版本、依賴套件、系統工具）封裝進一個 Image，確保無論在開發者電腦、測試伺服器還是生產環境，執行結果都完全相同。AI Agent（如 Cursor、Claude Code）現在能直接根據你的專案結構生成 Dokerfile，你只要提供上下文，它們就會自動處理環境定義，大幅降低配置錯誤的風險。

2 從 zero 開始：建立第一個 Dockerfile

讓我們用一個簡單的 Next.js 專案範例。先在專案根目錄建立名為 Dockerfile 的純文字檔案（無副檔名），然後請 AI 幫你生成基礎內容。核心指令包括 FROM（選取基礎鏡像）、WORKDIR（設定工作目錄）、COPY（複製檔案）、RUN（執行命令）、EXPOSE（宣告連接埠）、CMD（容器啟動時的預設指令）。

3 實戰指令：建構與執行

使用以下指令將專案打包成 Docker Image 並在本機執行。注意使用 bun 作為包管理器可加速依賴安裝。

# 建構 Docker 映像檔（假設使用 Node.js 20 與 Bun 基礎鏡像） $ docker build -t my-nextjs-app . Sending build context to Docker daemon 2.048kB Step 1/8 : FROM oven/bun:1-alpine ... Successfully tagged my-nextjs-app:latest # 啟動容器，將容器內 3000 port 對應到本機 3000 $ docker run -p 3000:3000 my-nextjs-app [nextjs] ready - started server on 0.0.0.0:3000 [nextjs] URL: http://localhost:3000
🔬 深入解析：為什麼容器能解決環境不一致？
鏡像層（Layer）與寫時複製（Copy-on-Write）如何讓環境可重现？

Docker 的核心設計是分层架构與联合文件系统。每個 Dockerfile 指令（如 RUN、COPY）都會產生一個新的只讀層（Layer），這些層疊加起來形成最終的鏡像。當容器啟動時，會在最上層掛載一個可讀寫層（Container Layer），所有變更都寫在這裡。這種設計帶來三大優勢：第一，快取機制：若某層未改變，Docker 會直接復用快取，加速建構；第二，環境隔離：容器內的檔案系統、網絡、進程都與主機隔離，不會互相干擾；第三，可移植性：鏡像包含所有依賴，只要 Docker 運行環境存在，就能在任何地方執行相同版本。AI 調用 Dockerfile 時，本質是在定義一組環境狀態快照，確保代碼的「生存環境」可被精確描述與重建。

2 對照：傳統部署 vs Docker 部署

傳統方式常因環境差異導致部署失敗，Docker 則提供一致性保證。

傳統部署（無 Docker）
# 開發機：Node 18 + npm 9 # 伺服器：Node 20 + yarn 1 # 結果：依賴版本衝突、編譯錯誤、運算結果不同
Docker 部署
# 開發機與伺服器使用同一個 Docker Image # Node 版本、依賴、系統庫完全一致 # 結果：建構一次，到處運行，行為可預期
4 Vibe 破裂診斷：容器啟動失敗怎麼查？

當容器啟動失敗（例如出現 Exit code 1 或無法連接），最常見的三個診斷步驟：第一，查看容器日誌：docker logs &lt;container_id&gt;，錯誤訊息通常會直接顯示；第二，檢查端口映射是否正確：docker ps 確認 -p 3000:3000 是否對應；第三，進入容器內部除錯：docker exec -it &lt;container_id&gt; sh，手動執行指令測試環境是否正常。AI Agent 可根據日誌輸出自動建議修復方案，例如替換錯誤的基礎鏡像或調整 COPY 路徑。

✏️ 小測驗

請先回答，再點擊「查看答案」

1. Dockerfile 中「FROM」指令的主要作用是什麼？
  • 設定容器的網絡端口
  • 指定建構所用的基礎鏡像
  • 定義容器啟動時執行的命令
✅ 「FROM」用於指定基礎鏡像（如 node:20-alpine），它是所有後續指令的起點。選項 A 是「EXPOSE」或「-p」參數的功能，選項 C 是「CMD」或「ENTRYPOINT」的作用。選擇錯誤會導致建構失敗，因為不知道從哪個環境開始層疊。
2. 以下哪個指令用於「進入正在運行的容器內部」？
  • docker inspect
  • docker attach
  • docker exec -it
✅ 「docker exec -it」會在容器內開啟一個互動式終端，適合除錯。選項 A 用於查看容器配置元數據，選項 B 用於附加到容器的標準輸入/輸出流，但無法執行新進程。錯誤使用會導致無法進行環境檢查或命令測試。

請依序完成以下練習

  1. 在任意純前端專案根目錄建立 Dockerfile，使用 Node 20 Alpine 鏡像，並完成建構與運行。
  2. 模擬 Vibe 破裂：故意在 Dockerfile 寫錯一個指令（如將 COPY 寫成 CYPY），觀察 Docker 建構時的錯誤訊息，並用 AI 協助修復。
  3. 使用 AI Agent（如 Cursor/Claude Code）生成一個支援 Bun 的 Dockerfile，比較手動撰寫與 AI 生成的差異，記錄它們如何處理依賴安裝與快取優化。
  4. 將你的專案推上 GitHub 後，嘗試在本機以外的環境（如本機 Docker Desktop）運行同一個 Image，驗證環境隔離效果。
