Phase 3: The Brain

記憶系統與知識庫

從個人偏好持久化到集體知識匯聚，建構不中斷的 Vibe Coding 體驗

🧠 為什麼記憶是 The Brain 的核心？

在 Vibe Coding 的流程中，AI 助手 不只是單次對話的工具，而是隨著專案推進持續累積理解的「合作夥伴」。記憶系統的角色，就是將你的程式碼風格、專案設定、常用工具鏈、甚至偏好的錯誤處理方式，從短暫的上下文窗口轉換為可跨對話存取的结构化資料。這讓 AI 能在第二週的對話中，依然記得你在第一週設定的 shadcn/ui 主題變數，或是在第三個分支中沿用你確立的 commit message 慣例。若沒有記憶層，每次新對話都像重新介紹自己，Vibe 的連續性會被硬生生切斷，開發節奏也隨之打亂。

1 個人記憶 vs. 共享知識庫

個人記憶（Personal Memory）是專屬於單一使用者與單一專案的偏好與歷史，例如你在 Cursor 或 Claude Code 中設定的 ~/.claude/settings.json 或 ~/.cursor/settings.json，裡面記錄了你偏好的 TypeScript 嚴格模式、忽略的 linter 規則、常用快捷鍵映射等。這些資料僅對你的帳號與裝置有效，AI 在每次對話載入時會讀取這些設定來調整回應風格。相對地，共享知識庫（Shared Knowledge Base）則是面向社群或團隊的集體知識，例如你在 GitHub repo 的 AGENTS.md 中記載的專案架構決策、在 biome.json 或 eslint.config.js 中公開的程式碼規範，或是存放在 .cursor/rules 目錄下的團隊指引。這些檔案會被推送到版本控制，所有協作者與 AI 工具都能讀取，形成可重複、可審閱的知識沉澱。

2 AI 如何實現「記住我的偏好」？

AI 工具的「記住我的偏好」功能，本質上是一個將非結構化對話歷史序列化到持久化儲存的過程。當你透過 Ctrl+I（Cursor）或 /memory 命令（Claude Code）新增一條記憶時，系統會將這段文字與當前上下文（專案路徑、檔案類型、甚至 timestamp）綁定，寫入使用者級別的 JSON 或 YAML 檔案。在下一次啟動對話時，工具會在載入專案根目錄的 AGENTS.md、.cursor/rules 或 ~/.claude/ 目錄後，主動將匹配的記憶片段注入初始 prompt 的系統訊息區塊。這種機制讓 AI 不需要你重複說明「用 Tailwind 的 ring 而不是 border」，因為記憶層已經替你把這個偏好編碼進了每次對話的開場上下文裡。

🔧 當 Vibe 破裂：記憶失效的診斷

最常見的 Vibe 破裂症狀是「AI 剛剛才記住的設定，下一個對話就不認得了」。診斷第一步是確認記憶檔案確實存在且路徑正確：在 macOS/Linux 上檢查 ~/.claude/settings.json 或 ~/.cursor/settings.json，在 Windows 上檢查 %APPDATA%\Claude\settings.json 或 %APPDATA%\Cursor\User\settings.json。第二步是檢查記憶是否被專案級的 AGENTS.md 或 .cursor/rules 覆蓋——若專案目錄下存在同名設定，專案層級通常優先於使用者層級。第三步是確認工具版本是否支援該記憶功能，舊版 Cursor 或 Claude Code 可能尚未實現跨對話記憶持久化。若檔案存在但 AI 仍忽略偏好，可嘗試清除快取並重啟工具，或直接在下一次對話開頭用 /clear 重置上下文後重新載入記憶。

🚀 實戰任務：讓 AI 記住一項專案偏好

請選擇你正在使用的 AI 編程助手（Cursor 或 Claude Code），執行以下操作：首先在專案根目錄建立一個 AGENTS.md 檔案，寫入兩行內容，第一行是 # 專案優先級設定，第二行是 在處理 React 元件時，請優先使用 tsx 格式並為每個 prop 加上 TypeScript 型別註解。。接著開啟新對話，輸入 幫我建立一個 Button 元件，觀察 AI 的回應是否自動套用 tsx 格式與 prop 註解。若沒有，請檢查 AGENTS.md 的語法是否正確（避免使用未封閉的 tag），並確認工具版本已更新。最後，嘗試在 Cursor 中使用 Ctrl+I 新增一條個人記憶：「當我提到 shadcn/ui 時，請使用 badge 組件而非 button 作為警示提示」，然後在另一個全新對話中輸入 顯示一個警告，驗證 AI 是否正確調用該記憶並選擇 badge 組件。

🔬 深入解析：記憶的載入時機與優先級
為什麼你的記憶有時被讀取、有時被忽略？

AI 工具載入記憶的時機並非隨機，而是遵循一套明確的層級與觸發條件。當新對話啟動時，工具會依序掃描四個來源：第一層是工具的全域設定（如 ~/.claude/settings.json），第二層是專案根目錄的 AGENTS.md 與 .cursor/rules/ 目錄，第三層是對話歷史中標記為「記憶」的片段，第四層是當前上下文窗口中自動提取的隱性偏好。優先級順序為：全域設定 < 專案規則 < 歷史記憶 < 隱性上下文。然而，若某個來源的檔案不存在或語法無效，工具會靜默跳過而不會報錯，這正是記憶「消失」卻難以追蹤的主因。此外，記憶的匹配並非全文比對，而是透過關鍵字觸發——例如你設定的記憶包含 shadcn/ui，則當對話中出現該字串時，工具才會將相關偏好注入系統訊息。若專案中完全未提及 shadcn/ui，即使記憶檔案存在，該偏好也不會被載入，這就是為什麼有些設定看起來「有時靈有時不靈」。
