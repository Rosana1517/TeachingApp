監控與分析（PostHog）

錯誤監控與用戶行為分析，讓 AI 知道修哪裡

1 PostHog 在 Vibe Coding 中的核心角色

在 Vibe Coding 的流程中，AI Agent 雖然能快速產生程式碼，但缺乏對「實際運作狀態」的直觀感受。PostHog 扮演了開發者的第二雙眼睛，它同時提供錯誤監控（錯誤率、堆疊追蹤）與用戶行為分析（事件追蹤、漏斗）兩大能力。當 Vibe 破裂時，AI 往往需要依賴你提供的具體錯誤訊息或現象描述才能有效除錯；而 PostHog 能自動將這些資訊結構化地回報給你。你可以透過 PostHog 的事件時間線，還原用戶在破滅前的操作路徑，讓 AI Agent 不再是盲目猜測，而是針對儀表板上顯示的異常事件進行精準修復。

2 手動除錯 vs. PostHog 數據驅動

觀察以下兩種除錯情境的差異，理解為何數據能加速 Vibe 恢復。

傳統手動除錯（無 PostHog）
1. 用戶在 Discord 留言：「按鈕點下去沒反應」 2. 你詢問：「是什麼瀏覽器？有看到錯誤訊息嗎？」 3. 等待用戶截圖，發現控制台有紅字 4. 將錯誤訊息複製貼上給 AI Agent 5. AI 嘗試修復，可能仍不知道觸發條件
PostHog 數據驅動
1. PostHog 儀表板顯示錯誤率突然上升 2. 你點擊錯誤詳情，看到完整堆疊追蹤與發生頁面 3. 開啟「行為流程」，發現 90% 的用戶在點擊按鈕後觸發了 500 錯誤 4. 直接將錯誤代碼與觸發事件名稱丟給 AI Agent 5. AI 立即定位到 API 處理函數並修復

PostHog 如何幫 AI Agent 縮短診斷循環？

Vibe Coding 的本質是讓 AI 快速迭代，但 AI 的「感知」受限於你提供的上下文。當應用程式在生產環境發生錯誤時，傳統開發者需要登入伺服器查看日誌，這過程耗時且容易遺漏用戶端的 JavaScript 錯誤。PostHog 的 JavaScript SDK 會在瀏覽器中攔截未處理的 Promise 拒絕與全域錯誤，並將錯誤訊息、堆疊追蹤、發生時的 URL 與用戶屬性打包發送回後台。這對 AI Agent 的價值在於：它不需要你手動重現問題，只需讀取 PostHog 的錯誤報告，就能獲得修復所需的精準線索。此外，透過「錯誤儀表板」設定的警報，當錯誤率超過閾值時，你甚至可以在 Discord 或 Slack 收到通知，讓 Vibe 的破裂在第一時間就被察覺。

✏️ 實戰練習：追蹤按鈕點擊事件

請先回答，再點擊「查看答案」

1. 在 Next.js 中使用 PostHog 追蹤自訂事件時，應該呼叫哪個方法？
  • posthog.track('event_name')
  • posthog.capture('event_name')
  • posthog.record('event_name')
✅ PostHog JavaScript SDK 使用 capture() 方法來記錄自訂事件。track() 是 Mixpanel 的 API，record() 並非 PostHog 的方法。正確寫法為 posthog.capture('button_clicked', { button_type: 'submit' })。
2. 下列哪項資訊不會被 PostHog 自動記錄在錯誤報告中？
  • 錯誤訊息與堆疊追蹤
  • 發生錯誤時的瀏覽器 User-Agent
  • 使用者在上一個頁面的完整輸入內容
✅ PostHog 會自動收集錯誤的技術細節（訊息、堆疊、瀏覽器資訊）與基本頁面屬性，但基於隱私考量，它不會自動記錄使用者輸入的敏感內容（如密碼或表單文字），除非你明確地在使用 capture() 時手動傳遞這些屬性。
🚀 今日任務

請依序完成以下練習

  1. 任務一：註冊 PostHog 並取得專案金鑰 前往 PostHog 官網註冊免費帳號，建立一個新的專案，並進入「專案設定」頁面複製「Project API Key」。這串金鑰是後續初始化的必要憑證。
  2. 任務二：在 Next.js 專案中安裝並配置 SDK 執行 npm install posthog-js，並在 app/layout.tsx 中引入 PostHogProvider，使用 useEffect 初始化 SDK，將你的 API Key 填入配置中。
  3. 任務三：埋入測試按鈕並觸發事件 在首頁新增一個按鈕，為其 onClick 事件加入 posthog.capture('test_button_click', { timestamp: Date.now() })，點擊按鈕後至 PostHog 的「事件」頁面確認該事件是否出現。
  4. 任務四：請 AI Agent 分析儀表板數據 將 PostHog 儀表板的截圖或事件列表貼上給 AI Agent（如 Claude Code 或 Cursor），並詢問：「假設這是生產環境的錯誤報告，你會建議如何修復？」觀察 AI 如何根據數據推斷問題根因。
