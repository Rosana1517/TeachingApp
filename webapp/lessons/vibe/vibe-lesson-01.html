Phase 1: The Core

Node.js 的角色

JavaScript 脫離瀏覽器後的完整運作原理，以及 AI Agent 是如何調用它來執行你的專案。

1 JavaScript 的兩條世界線

JavaScript 原本是一種「瀏覽器內嵌語言」——它只能活在 Chrome、Safari 這種瀏覽器裡，負責讓網頁動起來（點按鈕、跳出提示框、修改畫面）。直到 2009 年，工程師 Ryan Dahl 做了一件事：把 Google Chrome 裡負責執行 JavaScript 的 V8 引擎 整顆抽出來，外面包一層 C++ 外殼，讓它可以脫離瀏覽器、直接在作業系統上執行。這個「脫離瀏覽器的 JavaScript 執行環境」就是 Node.js。從那一刻起，JavaScript 不再只是「網頁裝飾語言」，而是能讀寫檔案、開伺服器、跑資料庫指令的正式後端語言。

2 瀏覽器 JS vs Node.js：能力大不同

同樣是 JavaScript 語法，能做的事情卻完全不同，關鍵在於「宿主環境」給了它什麼權限：

瀏覽器裡的 JavaScript
document.querySelector('#btn') .addEventListener('click', () => { alert('哈囉！') }) // 出於安全考量，不能直接讀寫 // 使用者電腦的檔案系統
Node.js 裡的 JavaScript
const fs = require('fs') fs.readFileSync('./data.json') const http = require('http') http.createServer((req, res) => { res.end('Hello from server') }).listen(3000)
3 AI Agent 調用 Node.js 的完整流程

當你對 Claude Code 說：「幫我建立一個 Next.js 專案，加入登入功能」，它背後其實是在你的終端機裡，一步步執行 Node.js 相關指令，而不是憑空生出一個網站：

$ npx create-next-app@latest my-app ✔ Would you like to use TypeScript? … Yes ✔ Would you like to use Tailwind CSS? … Yes Creating a new Next.js app in /Users/you/my-app... # AI 接著會安裝登入功能需要的套件 $ npm install better-auth # 最後啟動開發伺服器——這一步才是「跑起來給你看」的關鍵 $ npm run dev ▲ Next.js 14.2.3 - Local: http://localhost:3000 ✓ Ready in 1.2s
⚠️ 常見報錯與除錯

當 AI 執行指令卻回報「command not found: node」，代表這台電腦根本沒裝 Node.js，或是安裝了但沒有加進系統的 PATH。這時候可以請 AI 帶你安裝，或改用版本管理工具 nvm（Node Version Manager）——它能讓你在同一台電腦上，針對不同專案切換不同的 Node 版本，避免「這個專案要 Node 18，那個專案要 Node 20」互相打架。

$ node -v command not found: node # 用 nvm 安裝並切換到指定版本 $ nvm install 20 $ nvm use 20 Now using node v20.11.0
🔬 深入解析：Event Loop 到底在忙什麼
為什麼 Node.js 只用一個執行緒，卻能同時處理成千上萬個請求？

Node.js 的 JavaScript 主執行緒其實只有一條，但它從不「傻等」。當程式呼叫像讀檔案、查資料庫、發送網路請求這類「慢動作」時，Node.js 會把這個任務丟給背後的 C++ 層（libuv）去非同步處理，自己立刻回頭繼續執行下一行程式碼。等到那個慢動作真的完成了，結果會被放進一個「回呼佇列（Callback Queue）」，由 Event Loop（事件循環） 在主執行緒閒下來的時候，一個一個把它們取出來執行。這就是為什麼你在終端機打 setTimeout(() => console.log('2秒後'), 2000)，程式不會被卡住 2 秒，而是會先往下跑，2 秒後才回頭印出結果——這種「非阻塞（non-blocking）」設計，正是 Node.js 能同時服務大量使用者、卻不需要開一大堆執行緒的秘密。

✏️ 小測驗

請先回答，再點擊「查看答案」

1. Node.js 的本質是什麼？
  • A. 一種新的程式語言
  • B. 把 V8 引擎帶出瀏覽器的執行環境
  • C. 瀏覽器內建的 JavaScript 引擎
✅ 正確答案：B。Node.js 是 Ryan Dahl 在 2009 年把 Chrome 的 V8 引擎抽出來，讓 JS 能在作業系統上直接執行，因此能讀寫檔案、開伺服器。
2. 為什麼瀏覽器裡的 JavaScript 不能直接讀寫使用者電腦的檔案？
  • A. 因為瀏覽器沒有安裝 Node.js
  • B. 因為瀏覽器基於安全考量限制了這項權限
  • C. 因為 JavaScript 語法不支援檔案操作
✅ 正確答案：B。瀏覽器是一個「沙盒」環境，出於安全考量刻意限制網頁程式碼存取本機檔案系統，Node.js 則是在受信任的伺服器/開發環境執行，所以擁有完整權限。
3. Node.js 的 Event Loop 讓程式具備什麼特性？
  • A. 阻塞式（Blocking），一次只能做一件事並等待完成
  • B. 非阻塞式（Non-blocking），慢任務丟出去後可以繼續做別的事
  • C. 多執行緒（Multi-threading），每個請求開一個新執行緒
✅ 正確答案：B。Node.js 用單一主執行緒搭配 Event Loop，把耗時任務交給背後處理，自己不被卡住，因此能非阻塞地同時應付大量請求。
