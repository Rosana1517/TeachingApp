Phase 1: The Core

Package Management（NPM/Bun）

依賴地圖與 package.json 的 AI 協作機制

1️⃣ Vibe Coding 中的依賴角色

在 Vibe Coding 流程中，package.json 是專案的「依賴契約」，它記錄所有套件的版本與功能邊界，而 AI Agent 必須精準讀取此檔案才能正確調用外掛或指令。當 AI 執行如 npm install lodash 時，它會先核對 package.json 中是否已存在該套件，若未列出則自動新增；反之若版本不符，AI 會觸發 lock 檔案更新機制，確保環境一致性。此過程直接影響 Vibe 是否穩定——若 lock 檔案與 manifest 不一致，AI 可能錯誤載入不兼容套件，導致執行報錯或行為異常。

2️⃣ AI Agent 如何處理衝突

當 AI 安裝新套件時，若發現版本衝突（如 A 套件要求 v1.0，B 套件需 v2.0），它不會自行升級或降級，而是觸發 npm ci 或 bun install 重新解析樹狀結構，並依據 package-lock.json 或 bun.lockb 決定實際安裝版本。此過程本質上是「依賴圖解的重新計算」，AI 會透過回溯每個套件的 peerDependency 與 engine 限制，尋找最符合的版本組合。若仍無法解決，AI 會回報錯誤訊息讓使用者介入，避免破壞已有功能。

未解決衝突
AI 嘗試強制安裝新版本 → 導致其他套件失效 # 現象：Vibe 破裂，出現 run-time 錯誤
AI 正确处理
AI 偵測到 conflict → 查詢 lock 檔案 → 依原樹結構回滾或維持 # 結果：環境一致，Vibe 保持穩定
3️⃣ 實戰：安裝與觀察變化

請在終端機中執行以下指令，安裝一個常用套件並觀察 package.json 與 lock 檔案的變動：

$ npm install @types/node --save-dev + @types/node@20.11.15 # 新增至 devDependencies 並更新 package.json $ cat package.json | grep types "devDependencies": { "@types/node": "^20.11.15" }
🔬 為什麼 lock 檔案如此關鍵？
為何 AI 不能只讀 package.json 就決定安裝哪些版本？

package.json 僅定義了套件的版本範圍（如 ^20.0.0），允許在符合 SemVer 規則下安裝任何次版修訂，這雖提升了彈性，卻也帶來潛在風險：同一專案在不同環境可能安裝不同版本，導致「在我電腦上能跑」的問題。lock 檔案則記錄了完整的依賴樹狀結構，包含每個套件的精確版本與其子套件的版本，確保每次安裝結果完全一致。AI 在調用時，優先依據 lock 檔案來重建環境，而非重新解析 tree，這是維持 Vibe 穩定的核心機制。若 lock 檔案被遺失或未提交，AI 將被迫重新解析，增加錯誤機率。

🛠️ 診斷 Vibe 破裂的技巧

當 Vibe 出現運行異常（如模組找不到、函式未定義），首先檢查 package-lock.json 是否与 package.json 版本匹配。使用 npm ls 可查看當前安裝的樹狀結構，比對預期版本。若發現重複或過時套件，可執行 npx npm-check-updates -u 統一更新。AI Agent 會自動偵測這類不一致並在啟動前建議修復。另一常見錯誤是 peerDependency 未滿足，例如 React 套件需要特定版本的 ReactDOM，若未正確安裝會隱藏錯誤，此時需檢查 npm audit 或 bun audit 輸出。

✏️ 知識測驗

請先回答，再點擊「查看答案」

1. 當 package.json 指定 lodash@^4.17.0，但 lock 檔案記載的是 4.17.20，執行 npm install 時會發生什麼？
  • A. 會強制升級到最新版本
  • B. 會直接使用 lock 檔案中的版本 4.17.20
  • C. 會拋出錯誤並提示手動更新 lock 檔案
✅ 正確答案是 B。npm install 的預設行為是使用 package-lock.json 中的精確版本來重建環境，以確保一致性。只有當 lock 檔案遺失或被刪除外，才會重新解析 package.json 中的範圍。A 錯在不會自動升級至最新版本，C 錯不會拋出錯誤，這是設計的預期行為。
2. AI Agent 在觸發 bun install 時，主要依據哪個檔案來決定安裝策略？
  • A. package.json
  • B. bun.lockb
  • C. node_modules 目錄
✅ 正確答案是 B。bun.lockb 是 Bun 專用的 lock 檔案，記錄完整的依賴樹狀與版本資訊，AI 在部署或啟動時優先讀取此檔案以快速復原環境。A 僅作為版本範圍參考，C 是安裝後的結果而非依據來源。
