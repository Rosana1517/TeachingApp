Phase 1: The Core

Package Management（NPM/Bun）

掌握 Vibe Coding 中的核心工具，讓 AI Agent 精準管理專案依賴與版本一致性

📦 依賴管理在 Vibe Coding 中的角色

package.json 是 Vibe Coding 中 AI Agent 理解你專案「要裝什麼東西」的起點，而 package-lock.json 則是它確保每次執行都能還原相同環境的承諾書。當 AI 調用 NPM 或 Bun 安裝一個套件時，它會先查閱 package.json 來決定要不要新增或更新依賴，接著再依照 package-lock.json 的鎖定版本去拉取對應的 tarball。若沒有 package-lock.json，AI 就可能在不同環境下拉出不同版本的套件，導致行為不一致甚至報錯——這就是 Vibe 破裂的常見原因之一。

2 對照小節：依賴衝突的兩種處理方式

當 AI 發現兩個套件需要不同版本的同個依賴時，它該如何選擇？以下是兩種典型情境的對比：

情境 A：AI 自動修復（有 lock file）
$ npm install lodash@4.17.0 > > 系統偵測到 package-lock.json 鎖定為 v4.17.0 > 因此直接沿用該版本，避免版本跳變 > >vibe stable ✅
情境 B：AI 重新解析無鎖（無 lock file 或被清除）
$ rm package-lock.json $ npm install lodash@latest > > AI 重新計算所有依賴樹，可能推導出最新版本 > 但若某套件不兼容新版，可能導致 runtime error > >vibe broken ⚠️
3 帶指令範例的小節：觀察 AI 如何修改 lock file

讓我們示範當 AI 必須修正依賴衝突時，它如何觸發 npm install 並修改 package-lock.json。這個過程不是隨機發生的，而是基於解析後的依賴樹與已有 lock 文件的差異比對後決定的。

$ npm install express + express@4.18.2 added 2 packages, and updated 6 packages in 3s # AI 檢測到 package.json 新增 express 依賴，自動更新 lock 文件版本映射 $ cat package-lock.json | grep -A2 "version": "version": "1.0.0", "lockfileVersion": 2, "requiresLock": true, # 確認 lock 文件版本已更新，包含新的 deps tree hash # 若出現「ERESOLVE INDETERMINATE VERSION CONFLICT」，代表 AI 無法自動解決
🔬 深入解析：為什麼 package-lock.json 是 AI 的「記憶庫」？
AI 如何透過 lock 文件實現跨環境一致性？背後的圖論與依賴解析邏輯是什麼？

AI Agent 在 Vibe Coding 中並非單純地呼叫 npm install，而是扮演一個依賴解析引擎的角色。當你要安裝某個套件時，AI 會從 package.json 讀取起始依賴樹，然後啟動深度優先搜尋（DFS）或 breadth-first search（BFS）來展開所有子依賴，同時記錄每個套件的版本範圍（如 ^1.2.0）。如果發現同一套件被多個路徑要求不同版本，AI 會嘗試「向上提升」（hoisting）或「向下壓制」以統一版本，此過程稱為 dependency resolution。package-lock.json 實際上就是一個序列化後的完整依賴樹快照，包含每個套件的 exact version、integrity checksum、以及 parent-child 邊界關係。當下次執行時，AI 会先比對當前 lock 文件與期望版本是否一致；若有差異，便重新解析並寫入新 lock。這種機制確保了即使在多台電腦或 CI 環境中，AI 的行為仍可預測且穩定。這就是為什麼當你刪除 lock 文件後，AI 可能會給你不同的套件版本——因為它的「記憶」被清空了，必須重新學習。

✏️ 小測驗：檢驗你的理解程度

請先回答，再點擊「查看答案」

1. 當你在 Vibe Coding 中看到 'ERESOLVE INDETERMINATE VERSION CONFLICT' 錯誤，最可能的原因是？
  • A. npm 伺服器暫時不可用
  • B. lock file 不存在或被損壞，導致 AI 無法比對版本一致性
  • C. 你有未提交的 Git 變更
✅ 正確答案是 B。此錯誤代表 AI 在解析依賴樹時發現了無法和諧共存的版本衝突，且由於缺少有效的 lock 文件或 lock 檔與 package.json 不匹配，它無法自動決定該採用哪個版本。這正是 Vibe 破裂的徵兆之一。A 是網路問題，通常會顯示 timeout 或 connection refused；C 與依賴無關，Git 狀態不會影響 NPM 的解析邏輯。
2. 以下哪種操作會讓 AI 重新生成 package-lock.json？
  • A. 執行 `npm update`
  • B. 執行 `npm install --save-dev something`
  • C. 修改 .gitignore 檔案
✅ 正確答案是 A。npm update 會讓 AI 根據 package.json 中的 semver 規則重新解析所有可更新的依賴，並更新 lock 文件以反映最新的樹狀結構。雖然 B 也會寫入 lock 文件，但它只是「追加」一個新套件，不觸發全面重算；C 完全不涉及 NPM 流程。在 Vibe Coding 中，AI 更重視「一致性」而非「增量更新」，所以全面重算才是真正讓 AI 重新驗證整個依賴生態的動作。

請依序完成以下練習
