Phase 1: The Core

Localhost 與 Port（連接埠）

電腦公寓理論，解決 EADDRINUSE 打架衝突

1 什麼是 Localhost？

Localhost 其實就是你自己這台電腦，它有一個固定的網路位址 127.0.0.1，意思是「回頭指向自己」。當你在瀏覽器打開 http://localhost:3000，你並沒有連到遠方的伺服器，而是連到自己電腦裡正在跑的那個開發伺服器。你可以把整台電腦想像成一棟公寓大樓，裡面有 65,536 個「房間」，這就是 Port（連接埠）——每個正在執行的網路服務，都必須先「登記」一個房號，外界才能敲對門找到它。

2 常見服務的預設房號

不同的開發工具，出廠時都有各自習慣使用的預設 Port，先認識這些數字，之後看到報錯訊息就不會慌：

前端開發常見 Port
3000 → React / Next.js 5173 → Vite (Vue/React) 8080 → Vue CLI / 通用 Web Server 4200 → Angular
後端／資料庫常見 Port
5432 → PostgreSQL 3306 → MySQL 6379 → Redis 27017 → MongoDB
⚡ 為什麼多個任務會打架？

作業系統有個規則：同一個 Port，同一時間只能被一個程式「獨佔」。當你已經開著一個 Vibe 專案佔用 3000 號房，這時又啟動第二個專案、AI Agent 也試著把它塞進同一間房，系統就會直接拒絕，並丟出以下錯誤：

$ npm run dev Error: listen EADDRINUSE: address already in use :::3000 # EADDRINUSE = Error Address Already In Use（地址已被使用）
🔬 深入解析：作業系統怎麼決定誰能用哪個 Port
為什麼 Port 不能像資料夾一樣被兩個程式同時打開？

每個網路服務啟動時，都要向作業系統執行一個叫做 bind() 的動作，向系統登記「我要用這個 IP + Port 組合來接收資料」。作業系統的網路層會維護一張表，記錄目前每個 Port 被哪個程式（Process ID）佔用；一旦有第二個程式想 bind 同一組 IP + Port，系統為了避免「兩個程式收到同一筆資料卻不知道該給誰」的混亂，會直接回傳錯誤拒絕這次請求，而不是讓兩個程式共享。這也是為什麼「換一個 Port」永遠是最快的解法——因為每個房間本來就只租給一位房客。

3 如何避免與排除 Port 衝突？

最直覺的解法是「換房」：手動指定一個沒人用的 Port 啟動服務。如果你想知道是誰佔用了那個房間，也可以直接查出佔用的程式並關掉它：

# 方法一：換一個 Port 啟動，兩個專案就不會打架 $ npm run dev -- -p 3008 # 方法二（macOS / Linux）：查出誰佔用了 3000，再結束它 $ lsof -i :3000 COMMAND PID USER ... node 12345 you ... $ kill -9 12345 # 方法二（Windows）：一樣先查 PID 再強制結束 $ netstat -ano | findstr :3000 $ taskkill /PID 12345 /F
✏️ 小測驗

請先回答，再點擊「查看答案」

1. EADDRINUSE 錯誤代表什麼意思？
  • A. 網路斷線
  • B. Port 已被其他程式佔用
  • C. Node.js 版本太舊
✅ 正確答案：B。EADDRINUSE = Address already in use，代表你要使用的連接埠已經被另一個程式佔用了。
2. http://localhost:3000 這個網址，實際上連到的是哪裡？
  • A. 遠端的雲端伺服器
  • B. 你自己這台電腦（127.0.0.1）
  • C. 你的路由器
✅ 正確答案：B。localhost 對應的 IP 是 127.0.0.1，意思是「回頭指向自己」，所以連到的是本機正在執行的服務。
3. 在 macOS/Linux 上，要查出誰佔用了 3000 這個 Port，該用哪個指令？
  • A. lsof -i :3000
  • B. npm install port
  • C. git status
✅ 正確答案：A。lsof -i :3000 會列出目前佔用該 Port 的程式與 PID，方便你進一步用 kill 結束它。
🚀 今日任務

請依序完成以下練習

  1. 啟動一個 Next.js 專案到預設的 port 3000
  2. 在不關閉第一個專案的情況下，再啟動另一個專案，刻意觸發一次 EADDRINUSE 錯誤並截圖
  3. 改用 npm run dev -- -p 3008 啟動第二個專案，確認兩者能同時運行而不打架
  4. 練習用 lsof -i（或 Windows 的 netstat -ano）查出目前佔用 3000 的程式 PID
  5. 進階挑戰：手動 kill 掉其中一個服務的行程，觀察瀏覽器再次整理頁面時發生什麼事
