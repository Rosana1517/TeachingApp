資源自動化（Icons/Images）

Lucide 與 Unsplash API 如何讓 AI Agent 自動生成視覺化介面

🎨 Vibe Coding 中的資源角色

在 Vibe Coding 流程中，圖標（Icons）與占位圖片（Placeholders）不僅是美化元素，更是 AI Agent 理解使用者意圖的輔助訊號。當使用者輸入「建立一個待辦事項清單」，AI 會自動選用 Lucide 的 PlusIcon、CheckIcon 來強化 UI 語彙；若涉及背景或情境感，則透過 Unsplash API 隨機拉取一張符合主題的高品質圖片作為氛圍襯托。這些自動化選擇讓開發速度大幅提升，同時減少設計決策負荷。關鍵在於 AI 必須能根據上下文「推斷」最適合的圖源，而非單純隨機插入。

🤖 AI Agent 的智能選擇邏輯

AI Agent 在使用 Lucide 時，會根據元件功能匹配圖標名稱（如 SettingsIcon 用於設定頁），並自動處理圖庫匯入路徑；對於 Unsplash API，則分析關鍵字（如「work」、「nature」、「city」）後，向端點 https://source.unsplash.com/random/800x600?work 發出請求，並回傳圖 URL 嵌入 <img src="..." />。 此過程完全自動化，無需手動尋找圖片。但若關鍵字模糊或未指定，AI 可能選出不相關圖，造成「Vibe 破裂」——例如把「金融儀表板」配上一張貓的照片。此時需主動調整提示詞或固定圖片來源。

2 對照小節：AI 智能 vs. 手動選擇

當你在描述需求時，不同的表述方式會影響 AI 對資源的選擇精準度。以下是兩種情境的對比：

情境 A（模糊提示）
「幫我畫一個漂亮的工作畫面。」 → AI 可能隨機選一張辦公室圖 + 不相關圖標
情境 B（明確提示）
幫我建立一個任務管理界面，使用 Lucide 的 TimerIcon 和 User2Icon，背景圖用 Unsplash 的 'focused work' 主題。」 → AI 精準匹配圖標與情境圖

🔬 深入解析：為什麼 AI 能自動選圖？機制背後的邏輯
AI 是如何知道該用哪張圖與哪個圖標的？其實它靠的是語義嵌合與預訓練模式識別。

在 Vibe Coding 環境中，AI Agent 並非真正『看見』使用者要什麼，而是透過自然語言處理（NLP）技術，將用戶的描述映射到其訓練數據中已定義的模式庫。例如，當提到「設定」或「選項」，AI 會觸發與 SettingsIcon 相關的權重；而像『remote work』、『coffeeshop』等關鍵字，則對應 Unsplash 中 tagged 為 those terms 的影像。這種映射來自於大模型在大量程式碼與界面案例上的觀察學習。此外，Lucide 提供的是 SVG 組件，可直接渲染在 React 中，無需額外圖檔載入，因此效率高且可樣式化。當使用者未明確指定時，AI 會基於『最佳實踐』『最常組合』進行預測性填充。這正是 Vibe Coding 的核心魅力：以 minimal input 獲得 maximal coherence。但一旦輸入含混，就會導致錯配的圖標或圖片，這時就需要人工介入修正提示詞或鎖定資源來源，維持 Vibe 穩定。

✏️ 小測驗：診斷你的資源選擇能力

1. 若在 Next.js 中使用 Lucide 圖標時出現 'Cannot find module 'lucide-react'' 錯誤，最可能的原因是？
  • A. 沒有安裝 lucide-react 套件
  • B. 圖標名字寫錯了
  • C. Next.js 版本太舊
✅ 正確答案是 A。錯誤訊息指出找不到模組，表示套件未安裝。需執行 npm install lucide-react 或 bun add lucide-react。B 選項錯誤是因為即使名字寫錯，也會先成功導入模組再報錯；C 選項無關，因為只要安裝正確套件，新版或舊版 Next.js 皆可支援。
2. 當 Unsplash 回傳圖片顯示空白或頻繁失敗，最常見的問題是什麼？
  • A. 網路連線中斷
  • B. 使用的 API 端點已過時或限制頻繁請求
  • C. 图片格式不被 Next.js 支援
✅ 正確答案是 B。source.unsplash.com 服務已不再推薦使用，因會頻繁失敗或返回空圖，且無速率限制。建議改用 unsplash.co 或 image.pollinations.ai 等替代方案。A 雖可能但不常見，C 則錯誤，因為 Next.js 支援多種格式（JPEG/PNG/WebP）。
