Phase 4: Agent Production 工程化

Agent 測試與品質保證：用測試框架驗證行為

建立自動測試，讓 AI Agent 不再只是「看起來工作」

🧪 為什麼 Agent 需要測試？

在 Vibe Coding 的節奏中，我們常常快速生成 Agent 程式碼，並依賴 AI 的自我修正來迭代。然而，這種方式缺乏外部驗證機制——Agent 可能在某次測試中表現良好，但下一次改進後卻出現意料之外的行為。這就是 Vibe 破裂的隱形時刻。Jest、Playwright 或 LangSmith 等測試工具，提供結構化的反饋，讓開發者（或 Agent 本身）能夠量化行為變化、捕捉回歸錯誤，並在部署前確認品質。Agent 測試的本質不是「證明程式碼正確」，而是「建立信心」：即使我們用 AI 生成程式碼，也能透過測試確保它在預期情境下可靠運作。當 Vibe 破裂時，測試報告往往比模糊的錯誤訊息更能指向根本原因。

1 Agent 測試的三個層次

Agent 測試可分為三個層次，每層針對不同維度的行為：單元測試（Unit Tests）驗證單個函數或工具的輸入輸出，例如確認 Function Calling 的參數格式正確；整合測試（Integration Tests）檢查多個組件如何協作，例如 Agent 呼叫外部 API 後能否正確解析回應；端到端測試（E2E Tests）模擬真實使用者情境，例如透過 Playwright 控制瀏覽器，觀察 Agent 是否完成整個工作流程。這三層如同建築的鋼筋、牆壁與外觀，缺一不可。在 Vibe Coding 中，我們往往跳過單元測試直接寫 E2E，但這容易讓問題難於定位——當 Agent 行為異常時，你無法知道是工具調用錯誤、API 回應格式變更，還是邏輯缺陷。

2 用 Jest 測試 Agent 的工具調用
無測試的 Agent
const agent = createAgent({ tools: [searchWeb, summarizeText] }); const result = await agent.run("請摘要這篇文章"); console.log(result); // 問題：我們不知道工具是否被正確調用， // 也不清楚參數是否符合預期。
有測試的 Agent
test("Agent 應調用 searchWeb 工具並傳入正確 query", async () => { const searchMock = jest.fn().mockResolvedValue("結果"); const agent = createAgent({ tools: [searchMock, summarizeText] }); await agent.run("請搜尋相關資訊"); expect(searchMock).toHaveBeenCalledTimes(1); expect(searchMock).toHaveBeenCalledWith({ query: "相關資訊" }); }); // 測試確保工具調用符合預期， // 即使後續修改 Agent 邏輯也不會影響行為。

🔬 深入解析
為什麼 Agent 的測試不能只依賴 AI 自我檢查？

AI Agent 在生成程式碼時，往往基於提示詞中的隱含假設，而這些假設可能未被明確驗證。例如，一個使用 Function Calling 的 Agent 可能被訓練為調用 searchWeb 工具，但若工具定義變更（如參數從 query 改為 keyword），AI 可能自動適應而繼續運作，卻未符合系統預期。測試框架提供外部錨點，強制驗證行為是否符合規格，而非依賴 AI 的「看起來合理」。此外，Agent 的輸出具有不確定性——相同的輸入可能產生不同的回應，因此測試應聚焦於結構性約束（如工具調用次數、參數格式、回應中包含特定關鍵字），而非具體內容。這種方法稱為「契約測試」（Contract Testing），它確保 Agent 在變化中保持核心行為穩定。

✏️ 小測驗

請先回答，再點擊「查看答案」

1. 以下哪一種測試最能確保 Agent 的工具調用參數正確？
  • 端到端測試，用 Playwright 模擬使用者操作
  • 單元測試，使用 jest.mock 模擬工具並驗證函數呼叫
  • 整合測試，實際呼叫外部 API 並檢查回應
✅ 單元測試透過模擬工具（如 jest.mock）可以精確驗證工具被呼叫的次數與參數，而不依賴外部服務。端到端測試關注整體流程，整合測試驗證組件協作，但兩者都無法隔離工具調用的細節。
2. 當 Agent 的測試失敗時，以下哪種做法最能加速除錯？
  • 忽略錯誤，讓 AI 重新生成整個 Agent
  • 查看測試報告中的具體失敗點，例如哪個 expect 斷言未通過
  • 增加更多的 AI 提示詞來修正行為
✅ 測試報告提供結構化的失敗資訊（如預期值 vs. 實際值），這比模糊的錯誤訊息更能定位問題。忽略錯誤或過度依賴 AI 可能掩蓋根本原因，導致問題重複發生。
