Phase 1: The Core

Git/GitHub 協作

從本地檔案到雲端分支，掌握 Vibe Coding 的核心同步流程

1️⃣ Vibe Coding 中的 Git 角色

Git 在 Vibe Coding 中扮演的是「版本同步的橋樑」。它不只是用來記錄代碼變更，更是 AI Agent 與開發者之間的信任共識機制。當 AI 自動修復錯誤、生成新功能時，git commit 代表一次有明確意圖的變更；而 push 到 GitHub 則是將這個人工智慧的決策正式登記入雲端歷史。若沒有 Git，AI 的每一次修改都將是孤島式的，無法被追蹤、回滾或協作，Vibe 因此失去一致性與可預測性。

2️⃣ AI Agent 如何調用 Git

在 Vibe Coding 環境中，AI Agent（如 Claude Code 或 Cursor）會自動偵測檔案變更並觸發 git add 與 git commit。它根據上下文理解哪些是有意義的修改，例如修正 Bug 或新增元件，並以如 feat: 添加使用者登入組件 的格式撰寫 commit message。若 AI 發現錯誤，它會先回退到上個穩定狀態（透過 git reset 或 checkout），再重新生成程式碼。這種「寫 → 檢查 → 提交 → Push」的自動流程，使 Vibe 能持續保持在一個一致且可驗證的狀態。

3️⃣ 帶指令範例的小節

以下展示在 Vibe Coding 情境下，AI Agent 如何執行完整的 Git 流程並處理常見問題。學習者可觀察 AI 如何自動判斷是否需要建立新 branch、如何避免衝突、以及在遇到 permission error 時如何提議修正。

$ git status On branch main nothing to commit, working tree clean $ echo "const hello = 'Hello World';" > src/hello.js $ git add src/hello.js $ git commit -m "feat: 新增 hello.js 測試檔案" [main 1a2b3c4] feat: 新增 hello.js 測試檔案 1 file changed, 1 insertion(+) create mode 100644 src/hello.js $ git push origin main ! [rejected] main -> main (non-fast forward) # AI 提示：遠端有新提交，建議先 git pull --rebase
🔬 深入解析
為什麼 Vibe Coding 要求 AI 必須嚴格遵守 git commit 語義，否則會導致 Vibe 破裂？

Vibe 的核心在於「可預測性」與「一致性」，而 git commit 的語義是這種一致性的基石。若 AI 隨意填寫 commit message 如 fix bug 而非 fix: 修正使用者驗證空指針異常，後續的代碼審查、自動回滾、CI/CD 流程都可能失效。更重要的是，當 Vibe 破裂（例如 AI 誤改關鍵檔案），開發者需要透過 git log 快速定位哪次提交導致問題。若 commit 缺乏意義，診斷時間將大幅增加，甚至導致錯誤無法還原。此外，AI 在執行 git rebase 或 merge 時，若 commit message 不清晰，也無法正確判斷哪些變更需要保留或跳過，最終造成衝突堆疊。因此，Git 不僅是工具，更是 AI 行為的可驗證記錄協議。

✏️ 小測驗

請先回答，再點擊「查看答案」

1. 在 Vibe Coding 中，AI Agent 自動產生 git commit 時，最推薦的語義格式是哪一種？
  • A. "update"
  • B. "feat: 新增使用者登入頁面"
  • C. "fixed something"
✅ 選項 B 正確。Semantic Commits 能清楚區分功能新增（feat）、修復（fix）、修飾（refactor）等類型，讓其他開發者或 AI 快速理解變更性質，並支援自動化工具（如 Semantic Release）依此決定版本號與 Changelog。選項 A 和 C 缺乏語義資訊，無法用於自動化流程或衝突分析。
2. 當 AI 執行 git push 時收到 non-fast forward 錯誤，最佳處理方式是？
  • A. 強迫 push：git push --force
  • B. 先 git pull --rebase 再重新提交
  • C. 忽略錯誤，繼續操作
✅ 選項 B 正確。non-fast forward 表示遠端已有新提交，強制 push（A）會覆蓋他人修改，導致資料遺失或不一致；忽略錯誤（C）會使本地與遠端脫節，Vibe 無法維持同步。正確的作法是先將遠端變更整合進本地（--rebase），再推送，確保歷史線性且完整，符合 Vibe Coding 的協作原則。
